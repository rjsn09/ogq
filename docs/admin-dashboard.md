# 관리자 대시보드 설정

1. Firebase 콘솔에서 프로젝트 `emojigenerator-f3391`의 Firestore 데이터베이스 `default`를 선택합니다.
2. `users/{관리자 Firebase Auth UID}` 문서에 Boolean 필드 `isAdmin: true`를 추가합니다. 문자열 `"true"`는 관리자 권한으로 처리하지 않습니다. 일반 사용자에게는 false를 설정하거나 필드를 생략합니다.
3. 해당 DB의 규칙 탭에 루트의 `firestore.rules`를 게시합니다. 다른 컬렉션에 기존 규칙이 있다면 유지하면서 병합하되, 기존의 포괄적인 쓰기 허용 규칙과 `users` 쓰기 규칙이 `isAdmin` 변경을 허용하지 않도록 제거하거나 제한합니다. Firestore의 허용 규칙은 OR로 평가되므로 새 규칙만 추가해도 기존 허용이 취소되지 않습니다.
4. 프론트를 재배포합니다. 관리자 계정으로 로그인하면 로그아웃 왼쪽에 대시보드 버튼이 나타납니다. 역할 변경은 실시간 반영하며 권한을 제거하면 홈으로 돌아갑니다.

규칙은 일반 사용자의 전체 컬렉션 조회와 자기 자신의 관리자 승격을 차단합니다. 클라이언트는 관리자 계정이라도 isAdmin을 수정할 수 없습니다. 역할은 콘솔 또는 신뢰할 수 있는 Admin SDK로만 설정합니다. 규칙 파일을 만드는 것만으로 원격 DB에 게시되지는 않습니다.

## 지표 정의

- DAU/WAU/MAU: 한국 시간 기준 오늘/최근 7일/최근 30일 생성 이벤트를 남긴 고유 UID. 단순 방문자는 별도 추이로 표시합니다.
- 퍼널: 선택 기간에 방문 → 생성 시작 → 생성 완료 → 완료일 다음 날 이후 방문을 순서대로 수행한 고유 UID. 기간 밖에서 시작한 사용자는 해당 기간 퍼널에 포함하지 않습니다.
- 재방문율: 기간 방문자 중 firstVisitAt의 날짜 이후 방문한 사용자 비율. 같은 날 다른 세션으로 방문해도 재방문으로 세지 않습니다.
- 주간 리텐션: 한국 시간 월~일 최초 방문 코호트가 이후 해당 주에 방문한 비율. 아직 끝나지 않은 주는 관찰 중입니다.
- 북극성: 선택 기간에 생성 완료 이벤트를 남긴 사용자 수. 화면의 목표 인원은 임시 설정이며 DB에는 저장하지 않습니다.
- 생성: 기준 캐릭터와 이모티콘 API 요청 모두 포함합니다. 24장 세트 완료만을 따로 집계하려면 이벤트에 stage와 requestId를 추가해야 합니다.
- totalGenerationTimes: 완료·실패·취소 요청의 누적 소요 시간(ms).

조회 범위는 최근 56일 이벤트와 전체 사용자 집계입니다. 초기 사용자 규모를 위한 구성으로, 데이터가 커지면 서버에서 일별 집계를 만드는 방식으로 전환합니다. 로그인 이전의 방문, 계측 이전의 기록, 탭 종료로 유실된 종료 이벤트는 복원하지 않습니다. 기존 세션별 방문 이벤트와 새 날짜별 이벤트가 전환 당일 겹칠 수 있으나 사용자 지표는 UID로 중복 제거합니다.

현재 자체 로그는 클라이언트에서 기록하므로 사용자가 자신의 집계값을 조작할 수 있습니다. 비용 정산이나 신뢰가 필요한 감사 데이터는 서버에서 기록해야 합니다.

## 확인 순서

- 일반 계정: 버튼 없음, users/user_details/events 목록 조회 거부, 자기 users의 isAdmin 변경 거부, 약관과 모니터링 저장 가능.
- 관리자 계정: 버튼 표시, 대시보드 조회 가능, isAdmin을 false로 바꾸면 화면 닫힘.
- events: visit/generation_start/generation_complete가 보이는지 확인하고, 다음 날 방문 시 return_visit도 확인합니다.
- 빈 데이터는 0 또는 —, 현재 주 리텐션은 관찰 중, 조회 실패는 오류와 재시도 버튼으로 표시합니다.
